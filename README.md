# KEIB 競馬予想

JRA の**実際の出馬表・オッズ・結果**で予想する競馬予想ソフトです。前4走の馬柱からスピード指数・展開・適性などを数値にし、レースを何万回もシミュレーションして各馬の勝率を出し、オッズと比べて期待値の高い買い目を提案します。**架空のデータは一切使いません。**

- **過去・今日・これから**のレースを開催日ごとに表示。発走までの時間、締切間近・結果待ちの状態を表示します
- **確定したレースは答え合わせ**：着順・払戻と、予想（◎や推奨買い目）が実際にいくら戻ったかを並べて表示
- **リアルタイム更新**：`npm run server` で、出馬表・オッズは発走が近いほど短い間隔（2〜30分）で、結果と払戻は発走10分後から自動で取り込みます
- 基準タイム・馬場差・騎手/厩舎成績・枠順傾向・予想の重みは、**すべて実際のレース結果から計算**しています

![KEIB の予想画面](docs/screenshot.png)

> 予想は参考情報であり、的中や利益を保証しません。オッズは取得した時点の値です。馬券の購入前に必ず JRA 公式の情報を確認してください。馬券の購入は20歳から。

開発の経過・いま行っている作業・引き継ぎ事項は、このページの最後の[開発日記（引き継ぎ資料）](#開発日記引き継ぎ資料)にまとめています。

## できること

| 画面 | 内容 |
| --- | --- |
| 予想 | 開催日（結果・今日・明日・これから）→ 競馬場 → レース。出馬表に印（◎○▲△☆）・AI指数（オッズを使わない評価）・勝率・複勝率・期待値。行を開くと馬柱（前4走）、評価の内訳、着順分布 |
| 結果 | 確定したレースは着順・タイム・上がり・払戻と、◎の着順・推奨買い目の実際の払戻を表示。開催日ごとに◎の成績（1着・3着内・単勝/複勝回収率） |
| 展開予想 | 通過順から脚質を推定し、逃げ・先行馬の数からペース（H/M/S）を予想。隊列図つき |
| 買い目 | 予算と戦略（的中重視・バランス・高配当）から、7券種（単勝〜三連単）の買い目と金額を提案。オッズ発表前は勝率だけ表示 |
| 重み付け | 10項目（スピード指数・近走・上がり・騎手・厩舎・適性・展開・枠順・状態・人気）。プリセット「総合」「AI単独」など |
| バックテスト | 学習に使っていない実際のレースでの的中率・回収率（実際の払戻）・累積収支・確率の当たり具合。直近の開催日を今の設定で検証することもできます |
| データ | 実データの更新状況。自分で用意した出馬表・過去走の CSV / JSON の取り込み |

## 使い方

### リアルタイム版（自分の PC で動かす）

```bash
npm install
npm run server     # http://localhost:8080
```

起動すると JRA 公式サイトから今週の出馬表・オッズと、発走後のレースの結果を取り込み、1分ごとに更新を確認します。画面も1分ごとに最新のデータを読み直します。JRA へのアクセスは 1.2 秒に 1 回までで、変わらないページはキャッシュします。

スマホなど外から見るときは、[cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) を入れて `npm run tunnel` を実行し、表示される `https://xxxx.trycloudflare.com` を開きます（URL を知っている人は誰でも見られるので、自分だけで使ってください）。

### GitHub Actions で自動更新して GitHub Pages で公開する（サーバー不要・無料）

データの自動更新は **Race day ワークフロー**（`.github/workflows/race-day.yml`）が行います。1回の実行の中で「JRA から取り込み → `data` ブランチの `data.json` を上書き push」を繰り返し、実行時間の上限（約6時間）が近づくと自分で次の実行を予約するので、止まりません（GitHub の `schedule` は 10分ごとの指定で 1日 2回、毎時の指定も動かない日があったため、再開用にだけ使います）。取り込みの間隔は `build-data` が状況から決めます：今日の未確定レースの発走 90分前から結果が出るまで 5分、それ以外の開催日と前日発売中（24時間以内に発走）は 20分、深夜（JST 0〜7時）と開催のない日は 1時間（開催一覧を見るだけ）。画面は github.io で開かれたとき、この `data.json` を先に読みます。手動で動かすときは Actions → Race day → Run workflow（分と間隔を指定すると固定、`relay`=1 なら終了後に自動運転に戻る）。止めるときは Actions → Race day → Disable workflow（実行中の run も Cancel）。Pages ワークフローはアプリ本体の更新（push）用です。

`.github/workflows/pages.yml` が、開催日（土日・月曜）の 9:00〜17:59 JST は10分ごと、金土日の夜（前日発売のオッズ）は30分ごと、木曜（出馬表の発表）に2回、JRA 公式サイトから最新の出馬表・オッズ・結果を取り込み、変わったときだけ GitHub Pages に公開し直します。前回公開した `data.json` を引き継ぐので、サーバーもデータベースもなしで直近4開催日の結果（予想の答え合わせ）が貯まっていきます。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする（ワークフローが自動で有効にできることもあります）
2. **Actions → Pages → Run workflow** で一度実行する。以後は上の予定で自動更新。予定（`schedule`）は **既定ブランチにあるワークフローだけ**が動く（このリポジトリの既定ブランチは `ccr-5f5023aa-ovwgr9` で、すでに予定どおり動いている）
3. 公開先：`https://<ユーザー名>.github.io/keib/`（このリポジトリなら <https://nomixio260-a11y.github.io/keib/>）

**1分ごとの本当のリアルタイム版を外から見たいとき**は、**Actions → Live → Run workflow**（最大5.5時間）。GitHub Actions のランナー上でリアルタイム版のサーバーを動かし、Cloudflare Tunnel（Quick Tunnel、アカウント不要）で公開します。URL（`https://xxxx.trycloudflare.com`、実行のたびに変わる）は実行の Summary と、GitHub Pages の画面上部の「リアルタイム版を開く」に出ます。公開中は GitHub Pages 側の10分ごとの更新も動き続け、Live が終わると案内は消えます。

## 予想のしくみ

1. **スピード指数**：走破タイムを基準タイムと比べて数値化。基準タイムは実際のレース結果から、競馬場×芝ダート×距離ごとの「2勝クラス・良馬場の勝ち時計」を、馬場状態の差・クラスの差と同時に推定します。さらに開催日ごとの**馬場差**（その日の勝ち時計のずれ）で補正します。80 が2勝クラスの勝ち馬の水準。
   `指数 = 80 + 1000 ×（基準タイム − 走破タイム）÷ 基準タイム + 2 ×（斤量 − 55）`
2. **ファクター**：近走の着順・着差・クラス、上がり3F（同じ条件の中央値との差）、騎手と厩舎の成績（実データ）、距離・コース・馬場・芝ダ・回りの適性、展開（脚質×ペース×直線の長さ）、枠順（コース別の実際の傾向）、状態（休み明け・叩き2戦目・斤量増減・馬体重増減・年齢）、人気。
3. **重みの推定**：各ファクターをレース内で標準化し、実際のレースで1〜3着の順番を最もよく説明する重みを推定します（プラケット・ルース尤度）。学習では各レースの時点で手に入る情報だけを使います。「総合」はAIのファクターと単勝オッズを同時に当てはめた重み、「AI単独」はオッズを使わない重みです。
4. **確率の計算**：重みを推定したのと同じプラケット・ルース（多項ロジット）モデルで、1〜3着のすべての並び（最大 4,896通り）の確率を厳密に足し合わせ、勝率・連対率・複勝率と全券種（馬連・ワイド・馬単・三連複・三連単）の確率を出します。シミュレーションの回数による揺らぎはありません（シミュレーションは4着以下の着順分布の表示にだけ使います）。
5. **期待値**：`期待値 = 的中確率 × オッズ`。単勝以外のオッズは単勝オッズから推定します（発走2時間前からは馬連・ワイド・3連複の実際のオッズ）。AIとオッズの見立てがずれた馬券ほど期待値が高く見える「勝者の呪い」を抑えるため、期待値の計算にはオッズの確率を混ぜます（標準50%）。
6. **機械学習（既定の重み付け）**：単勝オッズの対数確率を出発点に、「オッズにまだ織り込まれていない分」だけを決定木の集まり（勾配ブースティング、レースごとのソフトマックス尤度をニュートン法で最適化）が学びます。特徴量は上のファクターに加えて、前走までのスピード指数の推移、通算成績、対戦成績の評価（相手の強さを考慮した着順の評価。イロ・レーティング）、複勝オッズと単勝オッズのずれなど 97項目（モデルが使うのは交差検証で選んだ 16項目）で、すべて発走前にわかる情報です。設定は学習期間の中の交差検証で選び（`npm run cv`）、検証期間は最後に1回だけ見ます。市場を出発点にするので市場より悪くなりにくく、上積みは小さいです（下の検証結果）。

## 「◎の勝率が低い」について

競馬は1レースに10頭以上が走り、いちばん人気の馬でも勝つのは3回に1回ほどです（JRA 全体でおよそ33%、2026年7〜9月は 36.6%）。単勝オッズには大勢の人の予想が織り込まれていて、公開されている情報だけでそれを大きく上回ることはできません。KEIB の◎は学習に使っていない期間で 36.6%（機械学習・総合）と、1番人気（36.2%）と同じ水準です。これは「予想が外れている」のではなく、競馬の勝率の上限がそのあたりにあるということです。勝ち馬の確率の当てはまり（対数損失）では機械学習が 1.873 と、オッズだけ（1.885）を上回ります（3年分・1万レースのデータと実験の繰り返しで得られた差で、これが公開情報の加工で届く範囲です）。

そこで KEIB は、どのレースなら当たりやすいかを **自信度（S/A/B/C）** で見分けます。学習に使っていない 864レースでは、自信度 S（約2割のレース）の◎は **60%** 勝ち、**86%** が3着以内でした（下の表）。自信度ごとの実績は本命のタイルとレース一覧にも表示しているので、当てたいときは自信度の高いレースに絞ってください（その分オッズは低くなります）。

- オッズの帯別では、馬連の 100倍以上（回収 37%）、ワイドの 30倍以上（78%）など、人気薄の組み合わせほど実際の回収率が低く、本命寄りの組み合わせ（馬連10倍未満 85.5%）のほうがましでした。穴狙いは不利です。
- 結論：**公開情報だけで、控除率（20〜25%）を上回る利益が出る買い方は見つかっていません。** KEIB ができるのは、平均的な馬券（75〜80%）より損を小さくすること（85〜90%）と、どのレースが当たりやすいかを見分けること（自信度）です。将来、オッズの推移（締切前の動き）や調教など、オッズにまだ織り込まれていない情報を加えれば変わる可能性はありますが、約束はできません。

オッズには多くの人の予想がすでに織り込まれているため、長期的に回収率100%を超えるのは非常に難しく、ここでも多くの買い方が100%を下回ります。過去の成績は将来の結果を保証しません。

## データについて

- 出馬表・オッズ・結果・払戻は JRA 公式サイト（www.jra.go.jp）の公開情報を、個人の分析用に取得しています。取得は 1.2 秒に 1 回までに抑え、変わらないページはキャッシュします。
- GitHub Pages に公開する `data.json` には、JRA から取り込んだ出馬表・オッズ・結果（直近4開催日＋今週）が含まれます。公開するかどうかは利用者の判断で、JRA のサイトポリシーを確認してください。集めた過去1年分のデータ（`data/history`）はリポジトリに含めません。
- 地方・海外のレースは馬場が違うため、スピード指数を計算しません。障害レースは予想の対象外です。

### 判断の記録（なぜそうしたか）

- **予想は単勝オッズにかなり近くなる**：オッズには多くの人の情報が織り込まれていて、データだけの AI より市場のほうがよく当たる。そこで「総合」では AI のファクターとオッズを同時に当てはめ、オッズにまだない情報だけを AI 側の重みとして残す（Benter 型の2段階モデルと同じ考え方）。期待値の計算ではさらにオッズの確率を50%混ぜ、AI とオッズのずれを過大評価しない（勝者の呪い対策）。
- **未来の情報を混ぜない**：学習・検証では、統計（基準タイム・騎手成績など）を学習期間より前のデータだけで作り、各レースの出馬表もそのレースより前の走だけで組み立てる（`preRaceCard`）。開催日ごとの馬場差はその日の結果だけで決まるので全期間で計算してよい（予想するレースより前の日の値しか使われない）。
- **前4走にそろえる**：JRA の出馬表に載るのが前4走なので、学習も4走にそろえている。
- **シミュレーションは推定したモデルと同じ形で**：重みはプラケット・ルースで推定しているので、シミュレーションも同じモデルで引く（正規分布の揺らぎだと確率がずれた）。着順ごとの温度も実データで推定する。
- **推定オッズで期待値を信じない**：オッズが実際にわかる単勝・複勝だけを既定の買い目にする。馬連〜三連単の推定オッズは、人気薄ほど実際の配当より高く出てしまう。
- **機械学習の設定は検証期間を見ずに選ぶ**：木の深さ・学習率・正則化・使う特徴量は、学習期間の中の交差検証（日付の連続した5ブロック）で選ぶ（`scripts/cv-gbdt.mjs`）。検証期間（2026-07-01 以降）の成績は最後に1回だけ確認する。検証期間は 864レースしかなく、◎の勝率の ±1.6 ポイント（標準誤差）や対数損失の ±0.002 は偶然で動く幅なので、検証期間の数字で設定を選ぶと偶然に合わせてしまう。
- **馬体重の特徴量は使わない**：交差検証では馬体重（絶対値・増減）を入れると悪化した（学習データでは利得の最も大きい特徴量に見えるが、過学習）。発走1時間前まで出ない情報でもあるので外した。
- **複勝オッズを特徴量に**：複勝は単勝と別の投票なので、単勝から見込まれる複勝確率（Harville）とのずれに情報がある。交差検証で市場のみの再校正（+0.0013）より良くなる（+0.0021）。
- **Artifact は外部と通信できない**：JRA を直接読めないので、`data.json` を一緒に公開し、開催日に定期的に作り直して公開し直す。本当のリアルタイムは利用者の PC の `npm run server`。

### つまずいた点（同じところで迷わないために）

- 全角→半角の変換（z2h）で「：」「（）」も半角になるので、正規表現は `[:：]` や半角の括弧で書く（父・母の父の名前の取り出し）。
- JRA はときどき HTTP 503 を返す → 3秒・6秒・12秒の間隔で再試行。
- `node --test` は `test/` 以下のファイルをすべてテストとして読むので、`node --test "test/*.test.mjs"` にしている（`test/fixtures` を外すため）。
- 作業環境（Claude Code のクラウド）の Bash では前面の `sleep` が使えない → 長い処理はバックグラウンドで動かし、終了通知を待つ。
- 日曜のレースのオッズは土曜の前日発売まで出ない（出馬表は木曜ごろに出る）→ その間は勝率だけ表示し、買い目は出さない。
- ルーティンが Artifact を公開したあとに手元から公開し直すと、Artifact ツールは「新しい版を見ずに上書きしようとしている」と断る → 公開中の `data.json` を `action: "read"`（`path: "data.json"`）で取り、`build-data --previous <その data.json>` で作り直してから公開する。
- ルーティンを手動で動かすとき（`fire_trigger`）にメッセージを付けると、それが2回目の依頼として扱われて同じ手順をもう一度始める → メッセージは付けない。
- 地方・海外の過去走（大井・香港など）はタイムを比べられないのでスピード指数を出さない。
- **結果の記録（`data/history`）の出走馬は着順で並んでいる**。これをそのまま出馬表にすると、同点のときに「行の並び順」で決まる特徴量（人気順位・スピード指数の順位など）に着順が漏れ、機械学習が「不可能な」成績（単勝◎の回収率 173%、新馬戦で指数のない馬を 83% の勝率で当てる）を出した。`preRaceCard` で馬番順に並べ直し、順位の同点は馬番で決めるようにして解消。学習の成績が良すぎるときは、まず漏れを疑う（新馬戦など情報のないレースで当たりすぎていないか見る）。
- **JRA の CNAME は「当日」と「過去」で種類が違う**（結果の開催一覧 `pw01srl00` / `pw01srl10`、結果ページ `pw01sde01` / `pw01sde10`）。過去の形だけで試験すると当日に動かない。当日のページで必ず確かめる。
- **GitHub Actions の schedule は信用しない**。10分ごとの指定で 1日 2回しか動かない日があり、毎時の指定も動かなかった。1回の実行の中でループし、終了前に自分で次の実行を予約する（race-day.yml。`workflow_dispatch` は GITHUB_TOKEN から起動できる）。schedule は再開用にだけ使う。公開リポジトリなので Actions の実行時間は無料。
- 機械学習の判定用データ（学習の最後の15%・約300レース）での早期終了は本数が大きくぶれる → 交差検証で本数を決め、学習期間の全部で固定本数を学習する（`FIXED_ROUNDS`）。
- 木の学習ライブラリ（`scripts/lib/boost.mjs`）の対数尤度は、同着（勝ち馬の行が2つ）のレースで両方を数える（1,000レースに1つほど）。設定どうしの比較には影響しないが、別の方法で計算した対数尤度と並べるときは約 0.003 ずれる（線形モデルとの混合の検証で見かけの差になった）。
